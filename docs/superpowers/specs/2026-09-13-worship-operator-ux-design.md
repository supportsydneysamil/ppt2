# 예배 운영 편의성 1차 개선 설계

날짜: 2026-09-13  
제품: 교회 예배용 웹 프레젠테이션 (제작 + 듀얼 스크린 송출)

## 제품 이해

이 프로그램은 PowerPoint 대체물이 아니라 **예배 현장 송출기**다.

- **제작자(주중)**: 예배 순서·성경·찬양 가사를 슬라이드로 빠르게 만든다.
- **운영자(주중/주일)**: Control 화면으로 다음 장을 미리 보고, 블랙아웃으로 전환을 숨기며, 프로젝터 Display에 실수 없이 넘긴다.
- **회중**: Display만 본다. 운영 UI는 보이면 안 된다.

핵심 성공 기준은 “예배 중 당황하지 않는 것”이다. 가독성(자동 폰트, 한영 동시)과 실시간 동기화는 이미 있다. 부족한 것은 **준비 속도와 운영 중의 인지 부하**다.

## 의도에서 나온 문제

1. 찬양/성경은 절 단위로 여러 장이 필요한데, 지금은 슬라이드를 하나씩 만들고 붙여넣는다.
2. 홈에서 바로 송출·복제를 못 해서 주일 아침에 에디터를 거쳐야 한다.
3. 운영 화면의 영문 상태/버튼과 빈 다음 슬라이드만으로는 “지금 뭘 눌러야 하는지”가 약하다.
4. 세션 `notes` API는 있는데 UI가 없어, 큐시트(기도자, 다음 순서)를 따로 적게 된다.
5. Display가 WebSocket 상태만 받고 `deck` 클로저가 늦으면 슬라이드가 안 바뀌는 레이스가 있다.

## 범위에 넣지 않는 것 (이번 사이클)

성경 API, 곡 라이브러리, 이미지 업로드/스토리지, 계정, 카운트다운 타이머, PPTX 레이아웃 고도화. 현장 운영에 바로 안 닿고 인프라가 커진다.

## 접근

기존 화면·API·SQLite JSON 모델을 유지하고, 순수 함수와 UI만 더한다. 새 의존성 없음.

## 기능

### A. 가사/성경 일괄 입력

빈 줄로 구분된 한국어(및 선택적 영어)를 여러 슬라이드로 쪼갠다. 선택한 슬라이드 **뒤에** 삽입한다. 영문이 없으면 `koOnly`, 한글이 없으면 `enOnly`, 둘 다 있으면 `koEn`. 개수가 다르면 빈 문자열로 맞춘다. 성경은 동일 `reference`를 모든 장에 복사한다.

### B. 슬라이드 추가 위치

제목/성경/가사/이미지 추가는 목록 끝이 아니라 **현재 선택 슬라이드 다음**에 넣는다. 선택이 없으면 맨 앞.

### C. 썸네일 식별

썸네일에 유형 라벨(제목/성경/가사/이미지)과 첫 줄 미리보기를 붙인다.

### D. 편집 안전장치

슬라이드 삭제 확인. 미저장 상태에서 탭 닫기 `beforeunload`. 테마 배경/글자색을 에디터에서 바꾼다.

### E. 홈

제목 검색, 복제(`제목 복사`, 새 slide id), 목록에서 바로 송출(기존 Display 창 배치와 동일).

### F. Control

운영 메모 textarea → 기존 PATCH `notes` 디바운스 저장. 연결/블랙/화이트 한글. Esc로 블랙아웃 해제. 다음 슬라이드 첫 줄을 큐로 표시.

### G. Display 동기화

`deck`을 ref로 최신 유지해 `SESSION_STATE`가 항상 현재 덱의 슬라이드를 고르게 한다.

## 오류

일괄 입력이 빈 텍스트면 슬라이드를 만들지 않고 안내한다. 복제/송출 실패는 홈에 기존과 같은 한국어 오류 문구. 메모 저장 실패는 콘솔 + 상태 문구.

## 테스트

`splitStanzaBlocks`, `slidesFromStanzas`, `slidePreviewText`, `insertSlidesAfter`에 단위 테스트. 기존 vitest 유지.
